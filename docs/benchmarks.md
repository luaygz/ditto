# Benchmarks

ditto makes three claims, each with its own evidence:

1. **Accuracy on real HTML with labels nobody on the project wrote**: SWDE (human labels from
   2011) and a Common Crawl silver set (labels from the sites' own JSON-LD), plus a LiveWeb-IE
   snapshot as a modern third-party check.
2. **Cost and speed**, which need no labels: tokens and LLM calls per 1,000 pages, pages per
   second per core.
3. **Clustering at scale** on synthetic sites whose true templates are known.

Every number on this page and in the README is written by `eval/report.py` from the newest
`eval/results/<name>/<timestamp>/` of an evaluation config, which `ditto eval run
eval/configs/<name>.yaml` produced. A config that has not run shows "not run yet", never a
number. Each results directory holds `results.json`, `results.csv`, `per_site.csv` and
`meta.json`; `meta.json` embeds the config, the model ids actually used, the prompt versions, the
git commit, the SHA-256 of every dataset manifest, the metric version, the machine and the
spend.

## Datasets

### SWDE

Hao, Cai, Pang and Zhang, *From One Tree to a Forest*, SIGIR 2011: 8 verticals (auto, book,
camera, job, movie, nbaplayer, restaurant, university) × 10 sites, human ground truth per
(vertical, site, attribute). The original CodePlex host is gone; `download.py` fetches the
archives from a GitHub mirror of the CodePlex export pinned to one commit, checks each archive's
size, git blob SHA-1 and SHA-256, and verifies the extracted tree by structure (80 sites, page
counts matching the directory names, one ground-truth file per attribute covering exactly the
site's pages). Ground-truth lines carry a page id, a value count and the values (count 0: the
page lacks the attribute); the parser is unit-tested on lines copied from the real files. Page
URLs come from each page's `<base href>`.

**Split rule** (`eval/datasets/swde/split.json`): per vertical, the two sites that sort first
alphabetically form the development slice, where tuning is allowed; the other eight per vertical
are the frozen test split. Field descriptions (`eval/datasets/swde/fields/<vertical>.yaml`, one
line per attribute) were written once, before any tuning.

### Common Crawl silver set

Modern HTML with labels from each site's own schema.org JSON-LD. The procedure, implemented by
`eval/datasets/commoncrawl_silver/`:

1. **Crawls**: the two most recent crawls listed by `index.commoncrawl.org/collinfo.json` at
   selection time (`domains.yaml` `crawls`).
2. **Shortlist** (`candidates.py`): well-known mid-size domains that render detail pages
   server-side, per vertical and target type: product (`Product`), job (`JobPosting`), recipe
   (`Recipe`), event (`Event`), plus books and news candidates. Each domain's status-200
   `text/html` captures are counted in both crawls' indexes (paged, cached on disk); domains
   with fewer than 5,000 distinct HTML URLs are dropped.
3. **Sample** 50 distinct detail-pattern captures per surviving domain, fetched by byte range
   from `data.commoncrawl.org`. Keep a domain when at least 60% of the sampled detail pages carry
   JSON-LD of the target type, the median visible text exceeds 200 words (not a JS shell), the
   captured `robots.txt` allows at least 90% of the detail URLs for both `CCBot` and
   `ditto-benchmark`, and at most 20% of the pages are login walls.
4. **Choose** 8 domains across 4 verticals, two per vertical, at most one per operator; every
   candidate's outcome and reason is in `domains.yaml` (`selected`, `rejected`) and
   `selection_log.json`.
5. **Download** (`download.py`): per domain, the newest capture per URL, every detail-pattern URL
   first, then a seeded sample of other URLs (at least 20% of the cap when available) so the
   site keeps its long tail, into `data/cc/<domain>/*.warc.gz`; the capture index
   `captures.jsonl.gz` (url, crawl, filename, offset, length, digest) is committed. The plan
   allowed 20,000 pages per domain. At 4 concurrent requests Common Crawl's CloudFront firewall
   blocked this machine's IP, so the downloader makes one request at a time, at least one second
   apart, backs off on 403/429/503, and the cap is 2,500 pages per domain; pages fetched before
   the change are kept (`argos.co.uk`). `domains.yaml` records the cap, its reason and the
   counts per domain.
6. **Labels** (`labels.py`): `extruct` on the original page; the page's JSON-LD object of the
   target type is flattened to the fields of `fields/<vertical>.yaml`. Labels are regenerated
   into `data/` and never committed.
7. **Noise check** (`noise_check.py`): 200 labeled pages sampled evenly across domains; every
   label value is looked up in the visible text the extractor sees (alternative spellings of
   durations, dates, enumerations and prices count); agreement per domain and field is recorded
   in `noise_check.json`. The reported check runs on the downloaded pages; until every domain is
   downloaded and labeled, the tables show the same check on the domain-selection sample
   (`selection_sample`), and say which. **This check was performed by the build agent (an
   automated script), not by a human.**
8. **Extractor input**: the page with every `<script>` block removed (JSON-LD included), exactly
   as in production. Microdata attributes stay because they are part of the visible DOM. ditto
   and every baseline see the same input.

The domains, their verticals, crawl ids and capture counts are in the results section below.

### LiveWeb-IE snapshot

*LiveWeb-IE: A Benchmark For Online Web Information Extraction*, ICLR 2026
([arXiv 2603.13773](https://arxiv.org/abs/2603.13773)): queries and ground truth for 15
permission-granted websites. `download.py` fetches the release (pinned commit, content digest),
snapshots the referenced pages with a polite fetcher (`robots.txt` obeyed per RFC 9309, at least
one second between requests per host, `User-Agent: ditto-benchmark/1.0
(+https://github.com/luaygz/ditto)`, hosts whose `Content-Signal` says `ai-input=no` excluded),
and records per-site status and exclusion reasons in `eval/datasets/livewebie/manifest.json`.
The release is licensed for non-commercial research only; the release and the snapshot stay in
the gitignored `data/`. Each site's queries are translated mechanically into a prompted-mode
`fields.yaml` (`build_fields.py`); `type_1`/`type_2` attributes are scalars, `type_3`/`type_4`
lists. Results are reported per complexity type as the mean field F1 over the fields each type's
queries ask for. Differences from the paper's protocol: ditto runs on a frozen snapshot, not the
live sites, and gets field definitions rather than free-form queries, so its numbers are not
directly comparable with the paper's. Paper numbers, if quoted, are labeled as the paper's.

## Metrics

As implemented in `src/ditto/evaluation/metrics.py` and `src/ditto/evaluation/clustering.py`.

**Three match columns**, every score computed in all three:

- `raw`: exact string equality.
- `norm` (normalized): C1 control characters read as cp1252, currency symbols removed, thousands
  separators removed between digits, whitespace collapsed, case folded, trailing punctuation and
  leading separators (such as `": "`) stripped, and plain numbers put in canonical form (`1.50`
  equals `1.5`). A value that normalizes to nothing counts as empty.
- `canon` (canonical, added in metric version 2): the `norm` form, then
  1. combining diacritical marks dropped (U+0300–U+036F after canonical decomposition): `Café`
     equals `Cafe`;
  2. a trailing `|` stripped like trailing punctuation: `Anchorage, AK, 99503 |` equals
     `Anchorage, AK, 99503`;
  3. a value made only of digit groups joined by single hyphens or spaces (an ISBN-10 may end in
     its check character `X`) and at least ten characters long without them is compared without
     the separators: `978-0307269997` equals `9780307269997`; shorter values such as dates
     (`1-12-2010`), ranges (`10-12`) or ZIP+4 codes are left as they are;
  4. on a `scalar` field only, a prediction made of two or more distinct label alternatives
     joined by `,` `;` `/` `|` or whitespace is correct (`Comedy Western` for the label
     `[Comedy, Western]`); every piece must be a whole labeled value.

  The `canon` form is a function of the `norm` form, so values with equal `norm` forms have equal
  `canon` forms (only a value made of separators alone, such as `- |`, becomes empty).
  There is no substring, containment or similarity matching: a value with different or extra
  content stays a miss (`Price: $12.99` against `$12.99`, `907/274-2739 | Reserve Online`
  against `907/274-2739 |`, `Ray Allen` against SWDE's `Ray Allen #20 SG`).

The `canon` rules were derived from the misses of the SWDE development slice only (the saved
predictions of ditto and the naive baseline; see `eval/analysis/swde_dev_misses.md`, regenerated
offline by `uv run python eval/analysis/swde_dev_misses.py`) and frozen as metric version 2
before any test set was rescored. Every `meta.json` records `metric_version` and
`match_columns`; results written before version 2 have no `canon` column and show `–` there.
Formatting differences the dev misses did not show (dates written differently, a leading field
label, units) have no rule. The same analysis classified a stratified sample of the remaining
dev misses as formatting, real errors or SWDE label problems (truncated, over-long or missing
labels, which no rule credits); the classification was done by the build agent, not a human,
and its estimate is in the README limitations.

**Units per field kind**, page by page:

- `scalar`: one unit per page. A list label holds acceptable alternatives; a list prediction is
  scored by its first non-empty item.
- `list`: one unit per item, multiset match.
- `record_list`: one unit per row after positional alignment; a row is correct when every labeled
  column matches.
- `key_value`: one unit per key; correct when the key exists with a matching value.

A null prediction where the label is empty is correct (a true negative, outside precision and
recall); a null where the label has a value is a miss (FN); a value where the label is empty is a
false positive; a wrong value is both a false positive and a miss. A field missing from a page's
label dict is not annotated there and is not scored on that page.

**Aggregation**: per field, counts are summed over a site's pages (micro); a site's precision,
recall and F1 are the mean over its fields; a vertical's the mean over its sites; the overall
figure the mean over verticals.

**Unseen pages only**: every spec records the pages its union page was built from
(`generated_by.pages_seen`: a base page plus donor pages, one to three for most templates); those
pages are excluded when ditto is scored, so every ditto accuracy number is on pages the LLM never
saw. Each table states how many labeled pages that removed.

**Like-for-like comparisons**: the baselines ran on fewer sites or on seeded page samples (see
*Budget-driven sample sizes*). Under every baseline row, a `↳ ditto, same sites and pages` row
recomputes ditto's F1 from its per-site results on exactly the sites the baseline scored and,
for a sampled baseline, on the same seeded pages (the `accuracy_sample` score each ditto config
with a page sample records), aggregated by the rules above; its cost columns are ditto's cost
pooled over those sites. If ditto lacks some of the baseline's sites, the baseline is rescored
on the shared sites too. The headline chart plots each such pair joined by a dotted line.

**Optional-field recall**: recall over (page, field) pairs where the attribute has a value on the
page but on none of the pages its template's spec was generated from.

**Unprompted mode**: the LLM names the fields, so per template its field names are aligned to the
label names by value overlap on a seeded sample of 50 pages (greedy one-to-one, an overlap on at
least 10% of the labeled pages required); the table reports recall of the labeled attributes
after alignment. **Schema precision** is the share of proposed fields that are attributes of the
page's main entity, judged field by field on 10 development sites by the build agent (the LLM
that built ditto), not by a human. The verdicts are committed in
`eval/judgments/swde_dev_schema_precision.json`; `ditto eval run
eval/configs/swde_dev_unprompted.yaml` recomputes the precision from them and lists proposed
fields without a verdict (`unjudged`) and verdicts for fields the run did not propose (`stale`).

**Clustering** against the true template ids: adjusted Rand index (Hubert–Arabie), purity (share
of pages in their predicted cluster's majority template), inverse purity, over-merges (predicted
clusters mixing two or more true templates) and under-merges (true templates spread over two or
more clusters). Unassigned pages count as singleton clusters.

**Union pages** (the v0.2 gate): tokens per template (tiktoken `o200k_base`) against the 30k cap,
and on synthetic sites whether every optional field appears in its template's union page as an
annotated candidate showing one of its values.

**Cost**: input and output tokens per 1,000 pages and LLM calls per template, with the model id.
Cached calls count with their original tokens, so a rerun reports the same cost. Dollars per
1,000 pages are derived from the tokens at standard-tier list prices in `config/prices.yaml` (no
cache, batch or flex discounts) for every method, so methods compare fairly.

**Spend**: the spend table gives, per evaluation, the LLM cost of the published run (its tokens,
cached calls included, at list prices: what rerunning it from an empty cache costs) and what the
runs kept under `eval/results/` were billed (`meta.json` `spend_usd`, from ditto's ledger; a
cached rerun bills $0). Both are ditto's own accounting. A billing check during the build found
the provider charging about 23% more than the ledger recorded over the same period (cause not
found; `DECISIONS.md`). The build's whole ledger per phase, development and tuning included:
`uv run python eval/report.py --spend-by-phase`.

**Speed**: pages per second per core for each stage, from the run's `timings.json` (pages ÷
(wall seconds × workers)), measured on the machine in `meta.json`; verification time excludes
the wait for repair calls. LLM latency (mean per uncached call) is reported separately. For
baselines, the table gives wall-clock pages per second, LLM calls included. The evaluation runs
time many small sites, each with a full worker pool, so their per-core figures include pool
start-up; `eval/bench/speed.py` times extraction alone on 2,000-page sites.

## Baselines

All baselines receive the same input as ditto, the page with `<script>` blocks (and styles,
comments and `<head>` except `<title>`) removed, and use the same main model, pinned in each
config. What a baseline does with that input is its own method: the naive baseline also prunes
attributes and collapses whitespace before its call; Crawl4AI runs its own HTML preprocessing.

- **Naive per-page LLM** (`eval/baselines/naive_llm.py`, prompt `prompts/naive_baseline.v1.md`):
  one main-model call per page returning every requested field; the accuracy ceiling and cost
  floor to beat. It runs on a seeded random sample per site; its cost per 1,000 pages is
  **extrapolated** from that sample (marked "extrapolated" in the tables). Its calls request the
  OpenAI Flex tier and fall back to the standard tier when Flex has no capacity, which happened
  for most calls; billing only, the cost columns use standard prices like every other method.
- **Crawl4AI** (`crawl4ai_schema.py`): `JsonCssExtractionStrategy.generate_schema` on one seeded
  sample page per template, the resulting CSS schema applied to every page of the template
  (scored on all labeled pages, its sample pages included). It isolates what the union page and
  verification add. Its token usage is captured by a hook on its completion helper, which
  recorded less than the ledger billed for the same calls, so its cost is likely understated.
  On the SWDE test split it ran on the sites finished within its budget, listed in its config.
- **AutoScraper** (Huang et al., EMNLP 2024; `autoscraper.py`): the upstream code cloned at a
  pinned commit with its model calls routed through ditto's LLM layer; its `eval` of model
  output is replaced by an integer parser because ditto never executes generated code. Per
  template it writes one rule per field from three seeded seed pages and applies it to the
  template's pages. For budget it ran on one SWDE test site per vertical, on the same seeded
  page sample as the naive baseline; its cost per 1,000 pages scales that sample's cost
  linearly, although on a whole site the per-template rules would be reused.
- **Hand-written XPath** (`handwritten.py`, `eval/baselines/handwritten/*.json`): ditto specs for
  five SWDE test sites (`auto-yahoo`, `book-barnesandnoble`, `movie-imdb`, `nbaplayer-yahoo`,
  `university-usnews`), **written by the build agent, not by a human**, from each site's first
  ten pages before any generated spec existed: the selector-quality ceiling. Scored on all
  labeled pages, the ten included.

## Protocol

- **Frozen sets**: the SWDE test split, the Common Crawl capture index, the LiveWeb-IE snapshot
  and synthetic seed 1 are recorded and hashed in `eval/datasets/*/manifest.json`; `meta.json`
  carries those hashes for every run. Tuning used only the SWDE development slice and synthetic
  seeds 101–199; the test split, the Common Crawl set, LiveWeb-IE and seed 1 were never tuned on.
- **Budget-driven sample sizes**: each config sets a spend cap (`budget_usd`) and, where a
  baseline is involved, a seeded page sample per site (`sample.pages_per_site`): 50 pages per
  site on the SWDE dev slice, 10 on the SWDE test split and 20 per Common Crawl domain, instead
  of the 200 the plan allowed, to fit the total LLM budget. ditto configs with a sample also
  score exactly those pages. Crawl4AI and AutoScraper ran on a subset of the SWDE test sites,
  listed in their configs. Sites run round-robin across verticals, so an evaluation stopped by
  its cap still covers every vertical; skipped sites are counted in the status column.
- **Extrapolation**: per-page baselines report cost per 1,000 pages from their sample; ditto's
  cost is measured on whole sites.
- **Models and prompts**: every config pins its model per role and fails if the LLM layer would
  use another; model ids and prompt versions of each run are in `meta.json` and in the tables
  below.
- **Judgments**: the Common Crawl label-noise check, the schema-precision judgment and the SWDE
  dev miss classification were performed by the build agent, not a human.
