# Benchmarks

ditto makes three claims, each with its own evidence:

1. **Accuracy on real HTML with labels nobody on the project wrote**: SWDE (human labels from
   2011) and a Common Crawl silver set (labels from the sites' own JSON-LD), plus a LiveWeb-IE
   snapshot as a modern third-party check.
2. **Cost and speed**, which need no labels: tokens and LLM calls per 1,000 pages, pages per
   second per core.
3. **Clustering at scale** on synthetic sites whose true templates are known.

Every number on this page and in the README is written by `eval/report.py` from the newest
`eval/results/<name>/<timestamp>/` of an evaluation config, which `ditto eval run
eval/configs/<name>.yaml` produced. A config that has not run shows "not run yet", never a
number. Each results directory holds `results.json`, `results.csv`, `per_site.csv` and
`meta.json`; `meta.json` embeds the config, the model ids actually used, the prompt versions, the
git commit, the SHA-256 of every dataset manifest, the machine and the spend.

## Datasets

### SWDE

Hao, Cai, Pang and Zhang, *From One Tree to a Forest*, SIGIR 2011: 8 verticals (auto, book,
camera, job, movie, nbaplayer, restaurant, university) × 10 sites, human ground truth per
(vertical, site, attribute). The original CodePlex host is gone; `download.py` fetches the
archives from a GitHub mirror of the CodePlex export pinned to one commit, checks each archive's
size, git blob SHA-1 and SHA-256, and verifies the extracted tree by structure (80 sites, page
counts matching the directory names, one ground-truth file per attribute covering exactly the
site's pages). Ground-truth lines carry a page id, a value count and the values (count 0: the
page lacks the attribute); the parser is unit-tested on lines copied from the real files. Page
URLs come from each page's `<base href>`.

**Split rule** (`eval/datasets/swde/split.json`): per vertical, the two sites that sort first
alphabetically form the development slice, where tuning is allowed; the other eight per vertical
are the frozen test split. Field descriptions (`eval/datasets/swde/fields/<vertical>.yaml`, one
line per attribute) were written once, before any tuning.

### Common Crawl silver set

Modern HTML with labels from each site's own schema.org JSON-LD. The procedure, implemented by
`eval/datasets/commoncrawl_silver/`:

1. **Crawls**: the two most recent crawls listed by `index.commoncrawl.org/collinfo.json` at
   selection time (`domains.yaml` `crawls`).
2. **Shortlist** (`candidates.py`): well-known mid-size domains that render detail pages
   server-side, per vertical and target type: product (`Product`), job (`JobPosting`), recipe
   (`Recipe`), event (`Event`), plus books and news candidates. Each domain's status-200
   `text/html` captures are counted in both crawls' indexes (paged, cached on disk); domains
   with fewer than 5,000 distinct HTML URLs are dropped.
3. **Sample** 50 distinct detail-pattern captures per surviving domain, fetched by byte range
   from `data.commoncrawl.org` (at most 4 concurrent requests, backoff on 429/503). Keep a domain
   when at least 60% of the sampled detail pages carry JSON-LD of the target type, the median
   visible text exceeds 200 words (not a JS shell), the captured `robots.txt` allows at least 90%
   of the detail URLs for both `CCBot` and `ditto-benchmark`, and at most 20% of the pages are
   login walls.
4. **Choose** 8 domains across at least 4 verticals, two per vertical, at most one per operator;
   every candidate's outcome and reason is in `domains.yaml` (`selected`, `rejected`) and
   `selection_log.json`. `download.py` then fetches up to 20,000 pages per domain (detail-pattern
   URLs first, then a seeded sample of other URLs, at least 20% of the cap when available, so the
   site keeps its long tail) into `data/cc/<domain>/*.warc.gz` and commits the capture index
   `captures.jsonl.gz` (url, crawl, filename, offset, length, digest).
5. **Labels** (`labels.py`): `extruct` on the original page; the page's JSON-LD object of the
   target type is flattened to the fields of `fields/<vertical>.yaml`. Labels are regenerated
   into `data/` and never committed.
6. **Noise check** (`noise_check.py`): 200 labeled pages sampled across domains; every label
   value is looked up in the visible text the extractor sees; agreement per field is recorded in
   `noise_check.json`. **This check was performed by the build agent (an automated script), not
   by a human.**
7. **Extractor input**: the page with every `<script>` block removed (JSON-LD included), exactly
   as in production. Microdata attributes stay because they are part of the visible DOM. ditto and
   every baseline see the same input.

The domains, their verticals, crawl ids and capture counts are in the results section below.

### LiveWeb-IE snapshot

Yang et al., *LiveWeb-IE*, ICLR 2026 ([arXiv 2603.13773](https://arxiv.org/abs/2603.13773)):
queries and ground truth for 15 permission-granted websites. `download.py` fetches the release
(pinned commit, content digest), snapshots the referenced pages with a polite fetcher
(`robots.txt` obeyed per RFC 9309, at least one second between requests per host, `User-Agent:
ditto-benchmark/1.0 (+https://github.com/luaygz/ditto)`, hosts whose `Content-Signal` says
`ai-input=no` excluded), and records per-site status and exclusion reasons in
`eval/datasets/livewebie/manifest.json`. Each site's queries are translated mechanically into a
prompted-mode `fields.yaml` (`build_fields.py`); `type_1`/`type_2` attributes are scalars,
`type_3`/`type_4` lists. Results are reported per complexity type as the mean field F1 over the
fields each type's queries ask for. Differences from the paper's protocol: ditto runs on a frozen
snapshot, not the live sites, and gets field definitions rather than free-form queries, so its
numbers are not directly comparable with the paper's. Paper numbers, if quoted, are labeled as
the paper's.

## Metrics

As implemented in `src/ditto/evaluation/metrics.py` and `src/ditto/evaluation/clustering.py`.

**Two match modes**, every score computed in both:

- `raw`: exact string equality.
- `norm` (normalized): C1 control characters read as cp1252, currency symbols removed, thousands
  separators removed between digits, whitespace collapsed, case folded, trailing punctuation and
  leading separators (such as `": "`) stripped, and plain numbers put in canonical form (`1.50`
  equals `1.5`). A value that normalizes to nothing counts as empty.

**Units per field kind**, page by page:

- `scalar`: one unit per page. A list label holds acceptable alternatives; a list prediction is
  scored by its first non-empty item.
- `list`: one unit per item, multiset match.
- `record_list`: one unit per row after positional alignment; a row is correct when every labeled
  column matches.
- `key_value`: one unit per key; correct when the key exists with a matching value.

A null prediction where the label is empty is correct (a true negative, outside precision and
recall); a null where the label has a value is a miss (FN); a value where the label is empty is a
false positive; a wrong value is both a false positive and a miss. A field missing from a page's
label dict is not annotated there and is not scored on that page.

**Aggregation**: per field, counts are summed over a site's pages (micro); a site's precision,
recall and F1 are the mean over its fields; a vertical's the mean over its sites; the overall
figure the mean over verticals.

**Unseen pages only**: every spec records the pages its union page was built from
(`generated_by.pages_seen`); those pages are excluded when ditto is scored, so every ditto
accuracy number is on pages the LLM never saw. When a config sets a page sample, ditto is also
scored on exactly the baselines' seeded sample (the extra row in each table).

**Optional-field recall**: recall over (page, field) pairs where the attribute has a value on the
page but on none of the pages its template's spec was generated from.

**Unprompted mode**: the LLM names the fields, so per template its field names are aligned to the
label names by value overlap on a seeded sample of 50 pages (greedy one-to-one, an overlap on at
least 10% of the labeled pages required); the table reports recall of the labeled attributes
after alignment.

**Clustering** against the true template ids: adjusted Rand index (Hubert–Arabie), purity (share
of pages in their predicted cluster's majority template), inverse purity, over-merges (predicted
clusters mixing two or more true templates) and under-merges (true templates spread over two or
more clusters). Unassigned pages count as singleton clusters.

**Cost**: input and output tokens per 1,000 pages and LLM calls per template, with the model id.
Cached calls count with their original tokens, so a rerun reports the same cost. Dollars per
1,000 pages are derived from the tokens at standard-tier list prices in `config/prices.yaml` (no
cache, batch or flex discounts) for every method, so methods compare fairly; `spend` is what
the provider actually billed and appears only in the spend table.

**Speed**: pages per second per core for each stage, from the run's `timings.json` (pages ÷
(wall seconds × workers)), measured on the machine in `meta.json`; verification time excludes
the wait for repair calls. LLM latency (mean per uncached call) is reported separately. For
baselines, the table gives wall-clock pages per second, LLM calls included.

## Baselines

All baselines receive the same input as ditto, the page with `<script>` blocks (and styles,
comments and `<head>` except `<title>`) removed, and use the same main model, pinned in each
config. What a baseline does with that input is its own method: the naive baseline also prunes
attributes and collapses whitespace before its call; Crawl4AI runs its own HTML preprocessing.

- **Naive per-page LLM** (`eval/baselines/naive_llm.py`, prompt `prompts/naive_baseline.v1.md`):
  one main-model call per page returning every requested field; the accuracy ceiling and cost
  floor to beat. It runs on a seeded random sample per site; its cost per 1,000 pages is
  **extrapolated** from that sample (marked "extrapolated" in the tables). Its calls use the
  OpenAI Flex tier, which changes billing only; its cost columns use standard prices like every
  other method.
- **Crawl4AI** (`crawl4ai_schema.py`): `JsonCssExtractionStrategy.generate_schema` on one seeded
  sample page per template, the resulting CSS schema applied to every page of the template. It
  isolates what the union page and verification add.
- **AutoScraper** (Huang et al., EMNLP 2024; `autoscraper.py`): the upstream code cloned at a
  pinned commit with its model calls routed through ditto's LLM layer; its `eval` of model
  output is replaced by an integer parser because ditto never executes generated code. Recorded
  as not run, with the reason, if it cannot run within the budget.
- **Hand-written XPath** (`handwritten.py`, `eval/baselines/handwritten/*.json`): ditto specs for
  five SWDE test sites (`auto-yahoo`, `book-barnesandnoble`, `movie-imdb`, `nbaplayer-yahoo`,
  `university-usnews`), **written by the build agent, not by a human**, before any generated spec
  existed: the selector-quality ceiling.

## Protocol

- **Frozen sets**: the SWDE test split, the Common Crawl capture index, the LiveWeb-IE snapshot
  and synthetic seed 1 are recorded and hashed in `eval/datasets/*/manifest.json`; `meta.json`
  carries those hashes for every run. Tuning used only the SWDE development slice and synthetic
  seeds 101–199.
- **Budget-driven sample sizes**: each config sets a spend cap (`budget_usd`) and, where a
  baseline is involved, a seeded page sample per site (`sample.pages_per_site`), below the
  200-page cap the original plan allowed, to fit the total LLM budget. Each table's "scored on"
  column states the sample. Sites run round-robin across verticals, so an evaluation stopped by
  its cap still covers every vertical; skipped sites are counted in the status column.
- **Extrapolation**: per-page baselines report cost per 1,000 pages from their sample; ditto's
  cost is measured on whole sites.
- **Models and prompts**: every config pins its model per role and fails if the LLM layer would
  use another; model ids and prompt versions of each run are in `meta.json` and in the tables
  below.
- **Noise check**: the Common Crawl label check was performed by the build agent, not a human.
